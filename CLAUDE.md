# CLAUDE.md — PCG_CORE (MEPCOM HRMIS)

Laravel **12** monolith (PHP ≥ 8.2; verified on 8.5.12 — target version, Blade, MySQL/MariaDB database `pcg_core`; upgraded from 9.52 keeping the Laravel 9 directory structure — Http/Kernel, RouteServiceProvider, config/*.php)
for the PCG Maritime Environmental Protection Command: personnel registration,
SOI profile, document review, 201 files, training tracks, MEPTDI LMS, OSAERT.
Read `docs/` before larger changes (enterprise HRMIS plan + open decisions: `docs/HRMIS_ENTERPRISE_PLAN.md`; org hierarchy lives in `org_units` / `App\Models\OrgUnit` — never hardcode commands/units); `docs/IMPLEMENTATION_ROADMAP.md` is the progress checklist — update it.

## Commands
```bash
composer install
php artisan test              # in-memory SQLite (phpunit.xml) — never the real DB
php artisan pcg:check         # read-only env/DB/folder health check
php artisan pcg:hash-password # bcrypt hash for ADMIN_PASSWORD_HASH
php artisan pcg:mail-test you@example.com  # send a test email, show active MAIL_* settings (password hidden)
php artisan db:seed           # sample data in EVERY app table (database/seeders); refuses unless APP_ENV=local and DB name ends in _dev
php artisan pcg:dev-seed      # the core sample set only (db:seed runs it first)
php artisan pcg:create-admin  # create an admin account (2FA set up at first sign-in)
php artisan pcg:personnel-sync [--apply] [--assign-to=MEPCOM] [--map-units=database/data/mepcom_units.json]  # copy approved registrations into the personnel master (dry run by default)
php artisan pcg:import-org-units database/data/mepcom_units.json [--apply]  # insert-only unit import (dry run by default)
php artisan pcg:purge-accounts --keep-admin=EMAIL [--keep-user=EMAIL] [--keep-since=YYYY-MM-DD] [--apply]  # delete test accounts + their records, keep the named ones (dry run by default; back up first)
php artisan pcg:reset-documents SERIAL [--reason=TEXT] [--apply]  # clear one member's required documents so they upload them again (dry run by default; back up first; files stay on disk)
php artisan pcg:schema-report [--table=NAME]  # read-only: table layout of the connected DB (no rows), to match the dev schema to Hermes
php artisan pcg:move-uploads [--apply]  # copy uploads out of public/ into private storage (never deletes)
php artisan pcg:file-keys init|status|rotate|retire|backup  # master keys for upload encryption (docs/FILE_ENCRYPTION.md)
php artisan pcg:files status|encrypt|verify|rewrap [--apply]  # encrypt older uploads, verify after a restore, rewrap after rotation
php artisan migrate           # additive pcg migrations only (back up first)
npm run build:css             # only after adding a Tailwind class not used anywhere yet
php artisan route:list
php artisan serve --host=127.0.0.1 --port=8000
# vendor/bin/pint exists but the codebase is not Pint-formatted; do not mass-reformat
composer audit
```
Windows helpers: `scripts/windows/setup.ps1`, `start.ps1`, `tailscale-serve.ps1`. Ubuntu/Debian server (nginx + PHP-FPM + MariaDB + Tailscale): `sudo bash scripts/linux/install-server.sh` (DEPLOYMENT_GUIDE §9) — not Hermes, which is Rocky Linux 9: the separate MEPCOM HRMIS deployment there (`/srv/mepcom-hrmis`, port 8010, own FPM pool, DB and Tailscale node, never touching AFPC/BioVerify/`/srv/pcg-core`) uses the isolated kit in `deploy/` (`deploy/README.md`; `preflight.sh` → `server-setup.sh` → `deploy\deploy.ps1 -Migrate` → `verify.sh`).
Browser end-to-end checks against a `pcg_core_dev` database: `tests/e2e/README.md`
(dev schema: `database/dev/schema_inferred.sql`).

## Architecture (actual)
- Routes: `routes/web.php`, grouped by audience:
  public · applicant (`auth`, `users` table) · unit checker (`unit.session`, `unit_users`; M1/all-units pages add `unit.m1`, role `m1_checker`) · admin (`admin.session` + `admin.audit` + `admin.role:...`; accounts in `admin_users` with roles (see AdminPermissions) and mandatory 2FA: one-time email code by default (`PCG_ADMIN_2FA=email`, needs MAIL_*), or authenticator app (`totp`); the `.env` admin only works while no account exists). Login forms use the named rate limiters in RouteServiceProvider (never `throttle:N,M`, which shares one counter per IP). Member saves use `throttle:member-writes`, member uploads `throttle:member-uploads`.
  Every new non-public route MUST be inside the right group; add it to `tests/Feature/AccessControlTest.php`.
- Controllers in `app/Http/Controllers` talk to the DB directly (mostly `DB::table`); ~30 tables have no model.
- Join key across tables: `serial_number`. For applicant writes always take it from `$request->user()`, never from input.
- Project config: `config/pcg.php` (admin creds, `upload_root`, `selfie_dir`, `trusted_proxies`). No hardcoded paths/URLs/credentials.
- Uploaded files live under `config('pcg.upload_root')` (must be outside `public/`; `pcg:check` fails otherwise); link them with `App\Support\Uploads::url()` (served by `FileController` at `/files/{path}` after an access check — never link upload folders directly). Every upload is AES-256-GCM encrypted: write with `App\Support\SecureFiles::store()/storeBytes()` (never `->move()`, `->store()`, `file_put_contents`; a test checks) and serve with `SecureFiles::respond()` after the access check (decrypts, streams, audits). Keys: `pcg:file-keys`, files: `pcg:files` — see `docs/FILE_ENCRYPTION.md`.
- Views: Blade. Admin pages extend `layouts/admin` (app shell; nav lives there — never add sidebars to pages); sign-in and public verification pages extend `layouts/auth`; the main landing page `/` is **PCG HRMIS** (`pages/pcg`, standalone, `css/pcg-home.css` + `js/pcg-home.js`, design taken from the PCG-CORE public site: official three-commands banner, Digital services, PCG organizational structure); MEPCOM HRMIS public information pages (home at `/mepcom` route `mepcom`, about, MEPTDI) extend `layouts/landing` (`css/landing.css`, content visible without scrolling; nav links back to PCG HRMIS); unit checker pages extend `layouts/unit` (pcg-ui shell; the review queue and dialog are `unit/partials/review` + `public/js/unit-checker.js` + `public/css/unit-checker.css`). Assets are self-hosted: `public/vendor/*` (pinned, see its README) and `public/css/tailwind.css` compiled from the views (`tailwind.config.js`). No CDNs. Vite is unused. Many links are root-absolute (`/profile`), so the app must be served at the root of a host/port with `public/` as document root.
- Personnel master: `personnel` (serial_number UNIQUE) + `personnel_assignments` (effective-dated; transfers close the current row, never edit history). Admin org scope: `admin_users.org_unit_id`; HRMIS routes use `admin.can:<capability>` (matrix in `App\Support\AdminPermissions`, roles super_admin/hr_admin/records_reviewer/records_approver/auditor/lms_admin/reenlistment_admin); 201 documents live in `config('pcg.document_root')` and are served only by `PersonnelDocumentController`; every personnel query goes through `App\Services\OrgScope`; pages that list everyone need `admin.orgwide`.
- Re-enlistment module (`ReenlistmentController`, `/admin/reenlistment`, capabilities `reenlistment.view` / `reenlistment.export`): non-officer registrations (`users.registration_type = non_officer`) by ETE; default list = ETE within 12 months (Asia/Manila dates); read-only, views and CSV exports audited. Role `reenlistment_admin` lands there and sees nothing else; its sign-in page is `/reenlistment/login`. It signs in with the password only (owner decision 2026-11-03, `PCG_ADMIN_PASSWORD_ONLY_ROLES`, never super_admin); every other admin role keeps the second step.
- Adjutant module (`AdjutantController`, `/admin/adjutant`, capability `soi.adjutant`, role `adjutant`, sign-in page `/adjutant/login` with the normal second step / OTP): records SOI 1.a Coast Guard Awards and Decorations (`reinlist_cg_awards_decorations`) and 3.a Coast Guard schooling (`reinlist_trainings`, category `coastguard`), with `added_by` = admin id (migration 2026_11_08_000003); limited to approved members whose serial has a current assignment in the Adjutant's `org_unit_id` (OrgScope). Members see these sections read-only and their SOI saves never delete or add them (owner decision 2026-11-08). Award types: `applicant/partials/cg-award-options` (the server accepts only those, via `App\Support\CgAwardTypes`). The old one-shot SOI save `/reinlist/store` is gone (it wiped Adjutant rows); the SOI saves only through `/temp-save/step1..6`. Database errors are logged with `App\Support\DbError::reason()` (never the values).
- Required documents (`personnel_data`, owner decisions 2026-11-09, `App\Support\DocumentReview`): while the record waits for the unit checker (status Pending, or no status on older rows, as on the checker's list) NOTHING can change: every box, every date, the pin and the Save and upload button are locked. After the checker's decision, documents with a file stay locked ("Accepted"); only returned items (the review clears them; `rejected_documents` comments shown on the box), never-filled boxes and clearances past their valid-until date open. Uploading an NBI/Ombudsman/Sandiganbayan clearance requires its valid-until date (today or later), on the page and on the server. The page and `ApplicantDocumentController::store` read the same row (`DocumentReview::rowFor`) and the server refuses whatever the page hides. Both unit review windows (`unit/dashboard`, `unit/dashboard_m1`) list all 10 documents plus a "Residence location" card (`docs[location]`): returning it clears latitude/longitude and adds a `rejected_documents` row `Residence Location`, marked complied when the member pins again. The checker queue leaves out records with no document and no pin (e.g. after `pcg:reset-documents`); they come back when the member uploads.
- 201 file review (owner decisions 2026-11-09, `App\Support\Review201`, migration 2026_11_09_000001 adds the nullable `personnel_201_files.status`): same rules as the required documents (waiting = all 11 sections and the Upload button locked; after review only returned and never-filled sections open; every upload goes back to Pending). Reviewed by own-unit checkers (their unit's members) and M1 checkers (all) at `/unit/201-files` (shared `unit/partials/review` in `mode` 201, posts to `unit.201files.review` → `UnitDocumentController::review201`); returned sections are `rejected_documents` rows `201: <label>`. Own-unit checkers may open their unit's 201 files (`FileController::inUnit201`).
- SOI submission lock (owner decisions 2026-11-09, `App\Support\SoiLock`, migration 2026_11_09_000002 adds nullable `users.soi_submitted_at`): the last SOI step asks "Is the data you entered correct?"; Yes saves step 6 and POSTs `/soi/submit`. From then on all six steps are read-only, blank fields included (`public/js/soi-lock.js`: typing, choosing, Add/Remove show "Unable to edit… contact your Adjutant or HR Unit Admin"; the step list and Next only navigate), and middleware `soi.open` refuses `/temp-save/step1..6`, `/profile/update` and `/soi/submit` (423 JSON). Reopen: `/admin/soi` (capability `soi.reopen`: super_admin, hr_admin, adjutant; scoped by OrgScope like the Adjutant module; reason required; audited `soi.reopened`). Direct editing (same capability and scope): `/admin/soi/{user}/edit` renders the member's own form (`DashboardController::soiPage`) in `layouts/admin` with `$adminEdit` (never locked, saves to `/admin/soi/{user}/step1..6`, step 6 "Save changes" without the submit prompt); `SoiSubmissionController::save` runs the member's `TempRegistrationController::saveStepN` with the member as `$request->user()`, audits `soi.edited` per saved step, and leaves `soi_submitted_at` as it is. Adjutant-recorded CG awards/schooling stay managed in `/admin/adjutant`.
- Confirmations: `data-pcg-confirm` on a submit button opens the in-page dialog (`pcgConfirm` in `pcg-ui.js`, `.pcg-confirm`; optional `data-pcg-confirm-title`, `-ok`, `-danger`), never the browser's `confirm()`. e2e flows that accept every confirmation call `autoConfirm(page)` from `tests/e2e/lib.js`.
- Own-unit checkers may only act on personnel with `users.mother_unit = session('unit_name')`; M1 checkers and admins see all. Keep `UnitDocumentController::review` and `FileController` consistent with that.

## Database safety (strict)
- `database/migrations/` holds only **additive** migrations written for `pcg_core` (admin_users, admin_audit_logs, contact_messages, lookup indexes). The original migrations, which do not match the real schema, live in `database/migrations/legacy/` and are never loaded. `php artisan migrate` (after a backup) is therefore safe; **never** run `migrate:fresh/refresh/reset` or `db:wipe` against `pcg_core`.
- New migrations must be additive, idempotent where possible, and reversible (down() undoes only what up() did).
- No DROP/TRUNCATE/mass DELETE; no schema change without: reason, impact, backup, reversible migration, rollback, validation, and the owner's approval.
- Never commit `.env`, dumps (`*.sql`), or files from `public/documents_toupload`, `public/201_files`, `public/disciplinary_actions`, `selfies/`.

## Coding conventions
- Match surrounding style (4-space indent, PSR-12-ish, Laravel helpers). Keep changes minimal; don't rewrite working modules.
- Validate every request (`$request->validate` or Form Requests); uploads need `file|mimes|max`, sanitised names, 0755 dirs.
- Use query builder bindings; `whereRaw` only with `?` placeholders.
- Escape output with `{{ }}`; no `{!! !!}` for user data; `@csrf` on all forms.
- Don't log passwords, tokens, selfies, or full `$request->all()` (PII).
- Status values are mixed-case in the DB (`Approved`/`approved`) — compare case-insensitively.
- UI: new/redesigned pages use `public/css/pcg-ui.css` tokens and `.pcg-*` components plus `public/js/pcg-ui.js` (no CDN, no inline scripts, no build step). Sign-in pages extend `layouts/auth`. Don't add new CDN dependencies.
- Insert server data into the DOM with `textContent`, or `escapeHtml()` when building HTML strings. `data-on-*` only calls page-defined global functions (built-ins like `eval` and library objects like `$`, `Swal`, `L` are refused); `pcg.submit-form` submits only the element's own form or one marked `data-pcg-submittable`.
- Sign-out is POST only (`route('admin.logout')`, `route('unit.logout')` with `@csrf`). Unit sessions are re-checked per request (`UnitUser::refreshSession`); unit checker actions go to `Log::channel('audit')`.
- One approved account per serial number (`User::serialTaken`, pending accounts reserve nothing); unit access matches the record owner (`personnel_data.personnel_id`; older rows without it: approved accounts only, `UnitUser::recordOwner`). Admin `/files` access follows `documents.view` / `documents.restricted` (selfies and photos too) and re-checks the admin session (`EnsureAdminSession::revalidate`). Creating checker accounts or setting their passwords needs `documents.restricted`. Upload names: `SecureFiles::storedName()` (never the original name).
- Hermes web settings live in `deploy/nginx` and `deploy/php-fpm`; apply changes with `deploy/update-web-config.sh`. Read-only server audit: `sudo bash ~/mepcom-hrmis-deploy/audit-server.sh`; the PHP pool has `open_basedir` (app folder and `/tmp` only). Never put the server address in git (`deploy/target.local`).
- Design rules (2026-11-09, `pcg-ui.css` end block): one accent (`--pcg-accent`: gold on member/public pages, cyan in the admin console); one solid call-to-action per screen (`.pcg-btn--cta`); Font Awesome icons only (no emoji); monospace only for codes people copy (`.pcg-mono`: serials, reference numbers); tabular numbers in tables and stats; headings balance-wrap; nested radius = outer − padding; every form submit shows a spinner automatically (`pcg-ui.js`; opt out `data-pcg-no-busy`; `window.pcgBusy(btn, on)` for fetch/JS submits); feedback motion only (`pcg-rise`, `.pcg-flash-row`, `.pcg-skeleton`), none under reduced motion. Headlines say the specific state ("5 records are waiting for your review"), not the page name.
- Phones/tablets: check with `node tests/e2e/responsive.js`; wide tables scroll in `.pcg-table-wrap` (added automatically by `pcg-ui.js`).
- CSP is enforced with `'strict-dynamic'`: **every** `<script>` (inline and `src=`) must carry `nonce="{{ $cspNonce ?? '' }}"` or it does not run (a test checks); `'unsafe-eval'` (Alpine) only where the template sets `@php(app()->instance('csp.allow_eval', true))`, the OpenStreetMap hosts only with `csp.allow_osm` (the residence map page); **no inline event handlers** (`onclick=` etc. — a test fails) — use `data-on-click="globalFunction" data-args='[...]'` (or `pcg.*` built-ins) handled by `public/js/pcg-ui.js`; no external origins.
- Personnel pages extend `layouts/personnel` (the SOI form `applicant/profile` too: it loads Alpine itself and sets `csp.allow_eval`); admin pages `layouts/admin`; registration extends `layouts/auth` (`public/js/register.js`). `layouts/app` is left only for the unused `applicant/soi_sample`.
- Admin theme: `layouts/admin` adds `public/css/pcg-console.css` (dark navy/graphite + cyan by default, light via the top-bar toggle, kept in `localStorage.pcgTheme`, set before paint). The top bar is a navbar (`public/js/pcg-navbar.js`): sidebar collapse to an icon rail on desktop (kept in `localStorage.pcgSidebar`, set before paint as `html[data-sidebar=collapsed]`), "Go to a page" search built from the sidebar links (`/` focuses it), pending-registrations bell for HR roles, account menu with Sign out. Style admin pages with the `--c-*` tokens / `pcg-*` components, never fixed colours; old Tailwind colour classes are remapped for dark only as a stopgap. The HRMIS overview (`/admin/hrmis`) is an interactive cross-filter (`public/js/hrmis-overview.js`, `public/css/hrmis-overview.css`) over rows the server sends already scoped by `OrgScope`, without birth dates or contact details; its CSV export posts the visible ids to `admin.hrmis.export`, which re-applies the scope and audits.

## Testing
- Feature tests create only the tables they need on SQLite (see `tests/Feature/AuthenticationTest.php`). PHPUnit 11: static data providers with `#[DataProvider]`.
- `AccessControlTest` fails if a route points at a missing controller method.
- For UI/flow changes, run the e2e scripts on a re-seeded dev database.
- Report results as Passed / Failed / Not tested / Blocked; anything needing the real DB is Blocked here.
